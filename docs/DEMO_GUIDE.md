# Demo guide (about 10 minutes)

Use https://smart-care-black.vercel.app and fictional accounts prepared as in [DEMO_ACCOUNTS.md](DEMO_ACCOUNTS.md). Do not show passwords on screen. Steps marked *(needs migration)* only work after the named SQL file has been run.

## 0. Before you start
- Two fictional patients (Patient A, Patient B), one doctor account, the admin account.
- Bookings are on weekdays (Mon–Fri) between 09:00 and 17:00 by default; pick a weekday.
- Open two browser windows (one private) so you can be signed in as two roles at once.

## 1. Patient: register and sign in (2 min)
1. Open `/register`, create Patient A with a fictional name. Point out that new accounts are always patients.
2. Sign in with the **Patient** tab. Mention that choosing the wrong role tab is rejected.

## 2. Patient: book an appointment (2 min)
1. **Book Appointment** → department → weekday date. The earliest available doctor and slot are suggested.
2. Choose a slot, keep priority **Normal**, confirm. Show the **queue token** generated by the database.
3. **Duplicate rejection:** book again with the same doctor and date, different slot → "You already have an appointment with this doctor on this date". Explain the partial unique index and that cancelled visits do not count.
4. **Slot clash:** as Patient B, try a slot Patient A already holds → the slot is not offered (and the database would reject it anyway).
5. *(needs `supabase_emergency_requests.sql`)* As Patient B, choose **Emergency / Urgent (reviewed by staff)** → the confirmation says "Emergency requested (pending staff review)", not "Emergency".

## 3. Patient: live queue (1 min)
Open **Live Queue Status**. *(needs `supabase_queue_status.sql`)* Show position, "now serving" and estimated wait. Explain that the position is computed in the database and the patient never receives other patients' data. Without the migration the page says "Live position unavailable".

## 4. Doctor (2 min)
1. Sign in with the **Doctor** tab.
2. **Queue:** emergency patients are listed first, then by token.
3. *(needs emergency migration)* **Approve emergency** on Patient B's request → B moves to the top.
4. **Start** a consultation, write notes and a prescription, complete it.
5. **Consultation History:** the completed consultation appears.
6. Back as Patient A, refresh **Live Queue Status**: the position and "now serving" have changed.

## 5. Admin (2 min)
1. Sign in with the **Admin** tab.
2. **Overview:** per-doctor counts (waiting, consulting, completed, emergency).
3. **Queue Control:** pick the doctor and date, **Call Next Patient**, complete, or cancel a no-show.
4. Cancel one of Patient A's appointments, then show Patient A can book that doctor again the same day.

## 6. Security talking points (1 min)
- URL guarding: as a patient, open `/admin` → redirected to the patient dashboard.
- The database enforces the rules: RLS per role, role changes blocked by a trigger, unique indexes for duplicates and slots, an advisory lock for token numbers.
- Keys: only the publishable key is in the browser; the secret key is never shipped.

## 7. Sign out
Use **Sign Out** in the sidebar for each role.
